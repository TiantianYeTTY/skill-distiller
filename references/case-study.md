# 工作案例：math-exam-review-report 的完整沉淀过程（2026-10-17/18）

本案例是 skill-distiller 的首个落地，供后续复刻时对照。

## 输入侧

- **定稿交付物**：《七年级期中考点梳理报告.docx》（七部分结构，冻结只读）；
- **原始 Prompt**：用户项目根目录的《期中考试考点梳理Prompt.md》（多年级合一 12 部分结构 + 教材知识树阶段——后被证明与定稿不一致）；
- **对话记录**：一个超长 session（经历多次压缩），含 10+ 轮用户修正；
- **记忆日志**：项目 daily logs（2026-10-17/18）与 MEMORY.md；
- **脚本**：`.workbuddy/analysis/` 下真实跑通的 style_docx.py、build_db.py。

## 三条证据线的实际产出

1. **格式硬规则（11 条）**：全部源自用户修正——公式一律 LaTeX、卷名+题号（禁 TXX）、讲考点必附完整原题且题目/答案分段、选项每项独立成段、原题块无底色、部分间无横线且间隔=回车空段落、页眉固定文案、零元信息、题图完整保留、变式标注来源、中间产物只进 .workbuddy/。
2. **错误档案（13 条）**：典型如——Unicode 上标糊弄公式（用户："所有的字母和数学公式都用 LaTeX"）；选项图片整个丢失（用户："2.6为什么选项没有了？"）；元信息写进正文（用户："你他妈写资料上干啥，这是我让你附带原题啊"）；已删内容在重生成时反复加回（用户："我他妈去掉的东西能不能不要再加回去？"）。每条都落到可执行的正确做法（如"生成后 grep 禁用字面必须全 0"）。
3. **方法论分诊**：原始 Prompt 保留其方法论内核（结论三级区分、逐题字段、覆盖率口径、干扰选项五列表、变式 8 项质检）；**显式弃用**其多年级合一报告结构与教材知识树阶段（与七部分定稿冲突），写明"不再采用"。

## 结构决策

- SKILL.md 写成五阶段（清点→数据库→内容→生成→质检），与实际操作顺序一致；
- 定稿 docx 的七部分结构与全部条目模板（3.2 拆解 / 3.3 陷阱 / 选择题页 / 变式题 / 易错表）连同真实片段进 report-template.md；
- 定稿样例 docx 本身复制进 skill 目录作为只读模板基准（用户随后也自行放了一份备份）；
- 质检 10 项清单全部写成可执行检查（grep/计数/解包核对）。

## 复刻要点

- 挖 transcript 时先找**最后一轮**定稿确认，再回溯全部修正——顺序反了会把已推翻的方案写成规则；
- "换场景适配什么"要写成脚本头部注释，而不是散在对话里；
- 硬规则数量不追求多，追求**每条都对应一次真实返工或明确否定**。
