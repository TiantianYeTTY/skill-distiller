# skill-distiller

> 把一段已完成、已定稿的 AI 工作对话，**蒸馏为可复用的新 Agent Skill**（对话→Skill 沉淀技能）。
>
> 从对话记录、记忆日志、真实脚本与定稿交付物中萃取格式硬规则、错误档案与方法论，按标准骨架生成可直接交接的 Skill 包——让"这次是怎么做成的"变成"下次照做就能成"。

## ✨ 这是什么

`skill-distiller` 是一个 Agent Skill（智能体技能包），解决一个非常具体的交接问题：

一次复杂任务（做一份报告、一个工具、一套文档）完成后，经验散落在四处——**对话记录**（含十几轮修正与返工）、**记忆日志**、**工作目录里真实跑通的脚本**、以及那份**定稿交付物**。换个会话或换个 AI，这些经验全部归零，同样的错会再犯一遍。

本技能把沉淀过程标准化为五阶段流水线，核心是**三条证据线萃取**：

1. **格式硬规则**——用户的每条不满/纠错 → 一条可验证的编号规则（重复出现、用户强调、导致返工的才够格）；
2. **错误档案**——「犯过的错误 → 用户反馈（保留原话，不得粉饰）→ 正确做法」三列表格，AI 自查发现的坑单独标注，不冒充用户反馈；
3. **方法论分诊**——用户最初的 Prompt 往往不完善：与定稿冲突的部分**显式写入弃用说明**，禁止静默丢弃或偷偷保留。

最终产出一个新 Skill 包：用户之后只需提供新材料 + 一句"按这个 Skill 做"，任何新会话都能稳定复现同等质量的产出，无需复述任何历史要求。

## 🎯 使用场景

当你的任务符合以下画像时，即可使用本技能：

| 要素 | 说明 |
|---|---|
| 前提 | 一次**已完成且用户定稿**的 AI 工作产出（报告/PPT/代码/工具皆可），没有定稿就没有模板基准 |
| 输入材料 | ① 定稿交付物（只读）；② 用户最初的原始 Prompt；③ 对话记录（transcript）；④ 记忆日志（如有） |
| 典型诉求 | "把前面所有的内容总结沉淀为一份可以复用的 Skill，以便后续 AI 交接，快速稳定产出同类成果" |
| 质量要求 | 所有踩过的坑都被记录且不再犯；规则可执行可验证；新会话零上下文也能照做 |

典型触发指令示例：

> 现在 <定稿交付物路径> 已经定稿了，不允许修改，可以作为一份模板。把前面所有的内容总结沉淀为一份可以复用的"<Skill 名称>"Skill，以便后续 AI 交接，能快速稳定产出 <复用场景>。我所有之前不满意的、下达过的要求需要被总结；你所有犯过的错误、以及如何改正都必须详细记录，以便之后不再犯相同错误。Skill 完成后，我仅需输入 <新输入> 和 Skill 即可稳定产出 <产出物>，无需其他额外 Prompt。

## 📦 安装

将本仓库克隆（或复制 `skill-distiller/` 文件夹）到 Agent 技能目录：

```bash
git clone https://github.com/TiantianYeTTY/skill-distiller.git ~/.workbuddy/skills/skill-distiller
```

重启会话后技能即被识别。之后用上面示例中的句式描述任务（附上定稿交付物路径），智能体会自动加载本技能；也可以显式调用 `/skill-distiller`。

## 🚀 使用方法（工作流概览）

技能按以下 5 个阶段自动执行，完整细节见 [SKILL.md](SKILL.md)：

| 阶段 | 内容 | 关键点 |
|---|---|---|
| 1. 素材收集 | 盘点真实用过的脚本与中间产物；解析定稿交付物的**真实结构**（解包看 XML，不凭对话记忆）；提取 transcript 中全部用户修正 | 只收真实跑通的脚本，实验废案不收 |
| 2. 三条证据线 | 萃取格式硬规则、错误档案（保留用户原话）、方法论分诊（保留/弃用显式判定） | 判定基准：定稿 > 用户后期修正 > 原始 Prompt |
| 3. 结构设计 | 按标准骨架生成 SKILL.md + references/ + scripts/ | 细节全部下沉 references，SKILL.md 保持精简 |
| 4. 写作规范 | 规则写成可执行可验证的检查动作（"生成后 grep 归零"），禁止口号 | description 必须含用户真实会喊的触发词 |
| 5. 验证交付 | 官方打包验证 → 自检清单 → 更新记忆 → 询问是否开源 | 发布 GitHub 必须经用户确认，不擅自发布 |

### 输入 / 产出

```
输入                                产出
──────────────────────────        ─────────────────────────────────────
定稿交付物（只读模板）      ───▶    <skill-name>/
原始 Prompt                 ───▶      ├── SKILL.md（N 阶段流程 + 红线速查）
对话记录 + 记忆日志          ───▶      ├── references/（模板/硬规则+错误档案/方法论）
真实用过的脚本               ───▶      └── scripts/（带适配指南头注释）
```

## 🔧 环境依赖

- **Agent 环境**（如 WorkBuddy）：需要能读取会话 transcript 与项目记忆日志、执行文件操作与命令
- **skill-creator 的 `package_skill.py`**（交付前官方验证）
- **gh CLI**（仅当用户确认开源发布时需要）

## ⚠️ 重要说明

1. **定稿交付物只读**：它是模板基准，任何情况下不得修改。
2. **错误档案保真**：必须保留用户反馈原话（哪怕是气话），不得改写粉饰；自查错误标注"（自查）"，不虚构用户发言。
3. **弃用决策显式化**：原始 Prompt 与定稿冲突的部分，要写明"不再采用"及原因——这是给未来 AI 的决策依据，静默丢弃等于丢失决策链。
4. **规则可验证**：写不进"怎么检查"的规则是空话，宁可不收。
5. **发布需确认**：开源到 GitHub 必须经用户确认，发布前做敏感信息扫描。

## 📁 目录结构

```
skill-distiller/
├── README.md                      ← 本文件
├── SKILL.md                       ← 技能正文：五阶段流程 + 红线速查 + 触发模板
└── references/
    ├── extraction-guide.md        ← 素材挖掘指南：transcript/记忆/定稿解析方法与硬规则判定标准
    ├── skill-blueprint.md         ← 生成骨架模板：SKILL.md/错误档案/脚本适配头 + 开源规范
    └── case-study.md              ← 工作案例复盘：首个落地 Skill 的完整沉淀过程
```

本技能没有预置 `scripts/`——脚本按"只收真实跑通过的"原则，在每次沉淀时从目标项目的工作目录收集。

## 🐛 踩坑与要点（节选）

来自 references/case-study.md 的首个落地案例（沉淀出一个初中数学考点梳理报告 Skill 并开源）：

- 挖 transcript 时**先找最后一轮定稿确认，再回溯全部修正**——顺序反了会把已推翻的方案写成规则；
- "换场景要适配什么"必须写成**脚本头部注释**，散在对话里等于没写；
- 对话中说过要改的东西未必真改了——定稿结构以**解包实际文件**为准；
- 开源推送被拒时，先 `git fetch` 看用户是否在网页端自行改过（很常见），rebase 合并并尊重其改动，**禁止 force push**；
